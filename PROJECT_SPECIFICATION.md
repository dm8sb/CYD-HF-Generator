# CYD HF Generator – Project Specification

This document contains only **requirements** (A-n, numbered and testable) and **decisions** (E-n, with rationale and measured values where they exist). Behavior as seen by the user (pages, controls, messages, log lines, examples) is described only in [USER_MANUAL_DE.md](USER_MANUAL_DE.md); [USER_MANUAL_EN.md](USER_MANUAL_EN.md) is its translation. Build instructions and the change history are in [README.md](README.md), architecture and development rules in [CLAUDE.md](CLAUDE.md).

---

## 1. Purpose and Use

A touchscreen-controlled 3-channel HF square-wave generator on the ESP32-2432S028R ("Cheap Yellow Display") with an SI5351 clock generator. It is used for experiments with HF mixers and for amateur radio training; low spurs and phase noise and an accurate IQ output matter more than feature count.

| Channel | SI5351 output | Function | PLL |
|---|---|---|---|
| CH1 | CLK0 | independent frequency | A |
| CH2 | CLK1 | independent frequency | B |
| CH3 | CLK2 | IQ follower of CH1 or CH2, phase 0/90/180/270° | PLL of its master |

Out of scope: WiFi, OTA, external buttons, waveforms other than square wave.

## 2. Hardware and Pinout

### 2.1 Board variants

Two boards are sold as ESP32-2432S028R. They differ only in the display controller; pinout, touch, backlight and CN1 are identical. One firmware serves both (E-18).

| Board | Recognized by | Display controller | RDDID (04h), measured |
|---|---|---|---|
| Original CYD | micro-USB port only | ILI9341 | `00 00 00` |
| CYD2USB | additional USB-C port | ST7789 type | `81 81 B3` (datasheet ST7789V: `85 85 52`) |

### 2.2 Pin table

This table is authoritative; README and manual repeat parts of it.

| Function | Bus | GPIO | Defined in |
|---|---|---:|---|
| TFT MOSI | HSPI | 13 | build flags (`platformio.ini`) |
| TFT MISO | HSPI | 12 | build flags; no internal pull (E-18) |
| TFT SCK | HSPI | 14 | build flags |
| TFT CS | HSPI | 15 | build flags |
| TFT DC | – | 2 | build flags |
| TFT RST | – | – (EN) | `TFT_RST=-1` |
| Touch MOSI / MISO / SCK | VSPI | 32 / 39 / 25 | `pins.h` |
| Touch CS / IRQ | VSPI / – | 33 / 36 | `pins.h` |
| SI5351 SDA / SCL (CN1, either order) | I2C | 22 / 27 | `pins.h` (`PIN_I2C_A`, `PIN_I2C_B`) |
| Backlight PWM | LEDC | 21 | `pins.h` |
| RGB LED R / G / B (active low) | – | 4 / 16 / 17 | `pins.h` |
| Free, input only | – | 35 | unused |

- GPIO21 is used only for the backlight PWM: never for I2C, buttons, LEDs or other peripherals, and never as an I2C candidate.
- Display and touch use separate SPI buses (HSPI, VSPI).

### 2.3 SI5351 module

- SI5351A with 25 MHz crystal, I2C address 0x60, 3.3 V supply, connected to CN1.
- Crystal load capacitance 10 pF (register 183 = 0xD2).
- Many breakout boards have an active-low `OE` pin: OE = GND enables the outputs.
- The original specification listed SDA = 27 / SCL = 22; the verified wiring is SDA = 22 / SCL = 27. Both work (E-17).
- Clones (e.g. MS5351M) with a different register 183 are accepted with a log warning (E-17).
- Duty cycle and output level at 50 Ω are not yet measured (MESSPLAN E5, F2).

## 3. Requirements

### 3.1 Outputs and frequency

- **A-1** CH1 and CH2 generate independent square waves of 8 kHz–160 MHz (`FREQ_MIN_HZ`, `FREQ_MAX_HZ`, E-16), nominally 50 % duty cycle, settable with 1 Hz resolution.
- **A-2** The requested frequency is stored exactly, not the rounded SI5351 value (E-9). The numpad rejects values outside the range; `+`/`−` clamp to it.
- **A-3** Each output can be switched on and off independently. A switched-off output is disabled via the output enable register and shows the off state selected in CONFIG (A-8). The GUI shows the channel state as ON / OFF (plus ERR, WAIT, NO HW), never the off state.
- **A-4** All outputs are off after power-up; the ON/OFF state is not stored (E-11). After a reconnection of the SI5351 the previous states are restored.
- **A-5** One drive strength (2 / 4 / 6 / 8 mA) applies to all outputs (E-2).
- **A-6** Tuning mode `Fractional` / `Low noise` / `Integer`, global, default `Fractional` (E-19):

  | Mode | MultiSynth | PLL | Tuning |
  |---|---|---|---|
  | Fractional | fractional | fixed 900 or 887.5 MHz | no dropout; the PLL changes (with reset) only where 900 MHz cannot reach ≤ 0.25 Hz |
  | Low noise | even integer (`MS_INT`) | fractional, takes frequency and correction | PLL changes without reset while the divider stays (VCO 600–900 MHz); reset when the divider changes |
  | Integer | even integer | integer, 24–36 × crystal (`FBx_INT` for even ratios, AN619 3.2.1) | nearest raster point crystal × a / MS |

  A mode change reconfigures all outputs; one brief dropout of running outputs is allowed.
- **A-7** Spread spectrum `Off` / `-0.5 %` / `-1.5 %` / `+/-0.5 %` on PLL A only (CH1, and CH3 with master CH1), modulation ≈ 31.5 kHz, default `Off` (E-20). The setting is written explicitly at init (`SSC_EN` = 0 for `Off`). Not available in `Integer`; switching to `Integer` turns it off. Switching it resets PLL A (brief CH1 dropout, IQ realignment).
- **A-8** Off state `Low` / `High` / `High-Z` (register 24, `CLKx_DIS_STATE`), global, default `Low` (E-21). It is written at init right after the identity check, before any output can be enabled; a change applies at once and does not touch running outputs.
- **A-9** A MultiSynth that is not needed is powered down (CLK2 while CH3 is not in IQ mode), unless the off state needs the output driver (E-21).
- **A-79** CH2 can be coupled to CH1 (E-52): CH2 = CH1 + offset, offset −160…+160 MHz in 1 Hz steps (`CH2_OFFSET_MAX_HZ`), CH1 stays freely adjustable and every CH1 change retunes CH2 on its own PLL B through the normal path (A-10). Outside 8 kHz–160 MHz CH2 waits (CLK1 off, WAIT while switched on, also switching on keeps it off) and starts by itself when CH1 + offset fits again; a CH3 with master CH2 follows CH1 + offset (A-18 applies to it). Coupling and offset are stored (default free, 0; missing keys keep free); `Defaults` and `*RST` set free and 0. While coupled a CH2 frequency is refused (`Result::Coupled`, SCPI/REST −221); decoupling keeps the frequency CH2 last ran at.
- **A-80** The screen can be turned by 180° (E-53) for mounting with the sockets on the other side: CONFIG `Device` → `Screen` → `Rotate` toggles 0° (default) and 180°, applied at once without a restart on both display controllers, with the touch following the rotated controls and the stored touch calibration valid in both orientations (the calibration wizard works in both). The orientation is stored (missing key: 0°); `Defaults` and `Factory` set 0°, `*RST` sets 0° in RAM like the backlight. Remote: SCPI `SYSTem:DISPlay:ROTation 0|180`, REST `config.rotation`.
- **A-10** A PLL is written and reset only when its parameters change. A reset affects only the PLL of the changed channel, never the channel on the other PLL. In `Fractional`, tuning a standalone output neither disables it nor resets its PLL, except for the rare PLL change of A-6.

### 3.2 Accuracy

- **A-11** Correction ±50 ppm in units of 0.01 ppm (`freq_correction`, positive = crystal runs fast). The crystal is modeled as 25 MHz × (1 + c × 10⁻⁸) and all dividers are computed against it with 64-bit integer math, so the correction is exact at every frequency. A change reconfigures the outputs without re-initializing the SI5351.
- **A-12** Maximum deviation of the synthesized from the requested frequency (register rounding only, correction assumed right):

  | Case | Limit | Host test |
  |---|---|---|
  | Standalone, `Fractional` | ≤ 0.5 Hz | ≤ 0.375 Hz at correction 0 |
  | Standalone, `Low noise` | ≤ 1.5 Hz | bound 25 MHz / 2^21 / 8 (divider 8 at 100 MHz); random frequencies max. 0.49 Hz |
  | IQ, `Fractional` / `Low noise` | ≤ 1.4 Hz | 1.32 Hz worst case (91 666 668 Hz) |
  | `Integer` | nearest raster point (kHz range possible) | – |
  | Standalone above 100 MHz (`Fractional`, `Low noise`) | ≤ 1.5 / 2 / 3 Hz up to 112.5 / 150 / 160 MHz | even integer MultiSynth 8 / 6 / 4 with a fractional PLL, bound 25 MHz / 2^21 / divider |

- **A-13** Fractions are the best rational approximation with a 20-bit denominator (continued fractions). VCO 600–900 MHz and the register limits of AN619 are kept. Accepted exception: in `Fractional` the fixed PLL of 36 × crystal exceeds 900 MHz by up to 45 kHz at +50 ppm.
- **A-14** The channel pages show the actual output frequency computed from the programmed registers (`actualHz()`), highlighted from 1 Hz deviation; with spread spectrum the mean frequency. MAIN shows the requested frequency, prefixed with `~` in `Integer` when the deviation is ≥ 1 Hz.

### 3.3 IQ (CH3)

- **A-15** CH3 has the frequency of its master (CH1 or CH2) and shares its PLL. All four phases 0/90/180/270° work over the whole IQ range 4.730–100 MHz (`IQ_MIN_HZ`, `IQ_MAX_HZ`) (E-7).
- **A-16** IQ pair: integer MultiSynth divider ≤ 127 (7-bit phase register; one unit = ¼ VCO period, so 90° = divider); 180°/270° = 0°/90° plus `CLK_INV` on CLK2. In `Fractional` and `Low noise` the divider is min(127, ⌊900 MHz / f⌋) with a fractional PLL; in `Integer` the PLL is integer as well.
- **A-17** Any change of PLL, divider or phase offset of an IQ pair disables both outputs, reconfigures them and resets the shared PLL to align the phases. A change of drive strength or inversion only is written without reset.
- **A-18** CH3 ON is a request (E-8): CLK2 runs only while the master is ON and inside the IQ range (4.730–100 MHz, narrower with spread spectrum on master CH1, see E-20). Otherwise CLK2 stays off without a dialog, the request is kept (WAIT) and CH3 starts automatically once the conditions are met.
- **A-19** If the IQ setup fails while the SI5351 answers, CLK2 is powered down, the master keeps running standalone, CH3 shows ERR and the setup is retried (A-37).

### 3.4 Settings and persistence

- **A-20** Settings are stored in Preferences/NVS, namespace `hfgen`. Every value is validated on load:

  | Key | Type | Content | Default | On load |
  |---|---|---|---|---|
  | `ch1_freq`, `ch2_freq` | U64 | Hz | 10 MHz, 14 MHz | clamped to 8 kHz–160 MHz |
  | `ch3_master` | U8 | 1 / 2 | 1 | invalid → default |
  | `ch3_phase` | U32 | 0 / 90 / 180 / 270 | 90 | invalid → default |
  | `backlight` | U8 | % | 80 | < 5 or > 100 → 80, otherwise nearest 10 % step |
  | `delta` | U32 | step in Hz | 1000 | nearest preset 1 Hz … 1 MHz |
  | `corr` | I32 | 0.01 ppm | 0 | clamped to ±5000 |
  | `drv_def` | U8 | mA | 4 | invalid → default |
  | `tune` | U8 | 0 Fractional, 1 Low noise, 2 Integer | 0 | invalid → default |
  | `ssc` | U8 | 0 Off, 1 −0.5 %, 2 −1.5 %, 3 ±0.5 % | 0 | invalid → default; Off in Integer |
  | `off_st` | U8 | 0 Low, 1 High, 2 High-Z | 0 | invalid → default |
  | `tc_x0`, `tc_x1`, `tc_y0`, `tc_y1` | I32 | raw touch values of the screen edges (x 0 / 319, y 0 / 239) | none | written by the calibration wizard; missing or implausible → default and wizard (E-27) |
  | `disp_panel` | U8 | removed | – | was written by the former boot gesture; deleted at boot (E-26) |

- **A-21** Missing keys give the defaults, so older NVS contents keep their behavior. The former keys `ch1_en` / `ch2_en` / `ch3_en` are ignored. Output states and the SDA/SCL assignment are not stored; the touch calibration is stored by its wizard, outside the autosave (E-27).
- **A-22** Autosave writes all settings 5 s after the last change (`SETTINGS_AUTOSAVE_MS`).
- **A-23** Without NVS the firmware runs with defaults and saves nothing. NVS unavailable at boot and a failed save each produce a dialog and a save state on CONFIG. A failed save keeps the change and is retried every 30 s (`SETTINGS_RETRY_MS`); the dialog appears once per series of failures.

### 3.5 User interface

- **A-24** LVGL 8 (8.4.0, E-28), 320 × 240 landscape, dark theme with colored cards. Pages: MAIN, CH1, CH2, CH3, CONFIG, NUMPAD, the touch calibration and the WiFi pages (WIFI with network scan and text entry, access point, device).
- **A-25** Page coordinates derive from the layout grid in `gui/gui_layout.h` (margin 8 px, header 38 px, card padding 6 px). No control is clipped or overlaps another. Pages do not scroll (E-42). Every page except MAIN has the same header: back button `◀` at the top left (one level up; CH1–CH3 and CONFIG go to MAIN), the title after it, page actions at the right; lists page with `▲`/`▼` (E-43).
- **A-26** Frequently used controls are at least about 36 px high; yellow buttons use dark text.
- **A-27** Colors: CH1 red, CH2 green, CH3 blue, CONFIG yellow, MAIN and back buttons gray. The RGB LED shows the color of the open channel page and is off on all other pages (E-3).
- **A-28** Frequencies are shown in MHz with grouped digits (`10.700 000 MHz`).
- **A-29** MAIN has no title header; it shows one tappable card per channel with state, frequency and its own switch, and at the bottom a status bar with save errors and the `CONFIG` button (concept W-E26; the cards open the channel pages). State and detail lines of the cards use 14 px, states other than OFF as filled labels (audit U-8). The channel pages (CH1–CH3) and CONFIG have a header with title and `MAIN` button; channel pages add the ON/OFF switch (request) with the actual state as on MAIN, `ON` / `OFF` / `WAIT` / `! ERR` / `! NO HW` (E-13). The card switches sit in their own column, at least 12 px from other touch targets (audit U-3).
- **A-52** Settings that change the signal compared to the defaults (off state, spread spectrum, tuning mode, drive strength) are visible on MAIN and on the channel pages, not only in CONFIG; off state `High` is shown in the warning color and needs a confirmation before it applies at the touch screen and in the web UI (audit U-2); remote sources (SCPI over USB, TCP and VXI-11, REST) may select it only with `Remote outputs: allowed`, under `local only` it is refused like switching an output on (SCPI `-221`, REST 403; E-40).
- **A-53** Touch targets: dialog buttons at least 120 × 40 px with at least 3:1 contrast to the dialog (audit U-4); buttons at most 8 px from the screen edge take taps up to the edge, without growing towards their neighbors (U-5); the header `MAIN` button is 36 px high; the CH3 master and phase chips are 6 px apart (U-6).
- **A-54** Contrast (WCAG 2.x, checked by `test_contrast`): text on colored buttons and chips in the color with the higher contrast (dark on CH1/CH2/CH3, at least 4.2:1), switch track and chip border at least 3:1 against the background (audit U-7). States other than OFF are filled labels, errors start with `!`, so they differ also without color (U-19).
- **A-58** The CH3 page sets the master frequency (tap on the frequency, numpad, back to CH3) and switches the master on while CH3 waits for it (audit U-16).
- **A-56** Lab operation (audit U-13): a screen lock (CONFIG, unlock by holding 2 s anywhere, the unlocking touch triggers nothing, not stored), a reset to defaults that keeps the frequency correction and the touch calibration and switches all outputs off, and a factory reset that erases the NVS and restarts; both resets need a confirmation.
- **A-57** The frequency correction can also be typed on the numpad (tap the value in CONFIG): signed, rounded to 0.01 ppm, at most ±50.00 ppm; a value outside is rejected and stays editable (audit U-11).
- **A-30** Frequency entry for CH1/CH2: step presets 1 Hz … 1 MHz, `+`/`−` with hold-to-repeat (from 0.6 s about 3 steps/s, after 3 s 10/s, after 6 s 20/s; pressure dropouts up to 70 ms keep the hold, audit U-20), tap on a digit selects the step (a separator selects the nearer neighbor, audit U-15), numeric keypad with validation (E-5) that rounds to 1 Hz exactly like remote input (half up, in integers, one shared routine for the numpad, REST and SCPI); a rejected input stays editable with the reason shown, the current frequency stays visible (U-9).
- **A-31** CONFIG contains, signal settings first, drive strength, off state, tuning mode, spread spectrum, correction (E-6), backlight (10–100 % in 10 % steps, E-23) and an info card (firmware version, branch, commit with dirty mark, build time, display controller with its source, SI5351 pins or state). Save errors are visible in every tab; the normal states `Saved` / `Saving...` are not shown on the device (E-44). CONFIG is divided into five tabs with at most three rows each, chosen on a tab bar at the bottom (E-42).
- **A-32** Touch: XPT2046 with a calibration per board (wizard with four corner crosses and a check cross, stored in NVS; fixed default calibration without one, E-27), jitter filter and debounce.
- **A-33** The backlight stays off until the first frame is drawn (the uninitialized panel shows noise).

### 3.6 Robustness and errors

- **A-59** Every controller setter reports its result (`Ok`, `NoChange`, `OutOfRange`, `Invalid`, `Conflict`, `Denied`, `HwError`); values are checked in their full type and never cut or clamped silently, only the `adjust*`/step functions of the GUI clamp to the range; the channel index is 1–2 (frequency) or 1–3 (output) strictly (V-1, S-12, W-E18).
- **A-60** The autosave writes only the NVS keys that changed; changes from SCPI (USB, TCP, VXI-11) are saved after 30 s of quiet, touch and web (REST) changes after 5 s; `Remote out.`, the network settings and the web password are saved at once outside the autosave; `*RST` sets the defaults in RAM without saving them until `SYSTem:SAVE`, and a later change saves only its own key (V-4, C-17, W-E17, W-E19). `SYSTem:SAVE` and `POST /api/save` write only the keys that differ from NVS (all after `*RST`), at most once per 10 s per source; a further request within 10 s is merged without an error and saved 10 s after the previous save (AF17, D26).
- **A-34** SI5351 errors never crash the firmware; they are logged, shown as a dialog where useful, and leave the outputs in a safe state.
- **A-35** Supervision every 2 s (`HW_CHECK_INTERVAL_MS`) reads back the output enable and CLK control registers. A failed transfer or unexpected content (e.g. after a power interruption) marks the SI5351 as lost (NO HW); the firmware tries to reconnect in the same cycle and then every 2 s, after one minute without the chip every 10 s (each attempt reopens the I2C driver for both assignments, PERF-11), and restores all outputs with their states.
- **A-36** Without SI5351 no output is configured and no repeated errors appear; all settings remain editable and are saved.
- **A-37** An output setup that fails while the SI5351 answers is shown as ERR (MAIN, header, info line), the switch keeps the requested state, and the setup is retried every 2 s without further dialogs (E-12).
- **A-38** Dialogs: at most one is open, further ones are queued, identical ones are not repeated; `OK` closes. Connection dialogs close by themselves after a reconnect; output error dialogs stay. The same holds for confirmation dialogs (two buttons), also for automatic questions (open fallback AP, web network change): an answer acts only on the dialog that showed it (generation per box, button by index), a question that is no longer needed is closed without effect, and the open fallback AP is allowed only while it waits for its question (audit CQ-1, CQ-15).
- **A-39** Serial log at 115 200 baud: boot line with version, branch, commit and build time; I2C, SI5351 connection and errors, display detection, touch, settings. Verbose output (frequency changes, register values, bus scan) only with `LOG_DEBUG 1` (E-14).
- **A-40** `Wire` is never accessed while the bus is not open (`I2CBus::isOpen()`).
- **A-61** The log output (own lines, LVGL and ESP-IDF log) is switchable between the serial port, a ring buffer of 32 lines and off, so a SCPI session over USB gets no log lines (V-5, C-16, W-E27). Control characters inside a line are written as `?`, SSIDs go through `Sanitize::text` (audit SEC-6). `SYSTem:LOG?` reads the buffer only for the USB source; over TCP and VXI-11 it answers `""`.
- **A-55** Touch test builds (`TEST_TOUCH_LOG`, `TEST_HIT_MAP`, own PlatformIO envs) log every touch and show a hit map for the operating tests; they are never released, the release env contains none of it, and CI builds the hit map env.
- **A-51** An internal error never freezes the device with running outputs: a failed LVGL assert (e.g. pool full) and a `loop()` blocked for 5 s (task watchdog) restart it; after the restart all outputs are off (A-4). Test hooks `TEST_LVGL_ASSERT` and `TEST_LOOP_HANG` (`config.h`) trigger both 20 s after boot.

### 3.7 Remote control

- **A-62** SCPI over the USB serial port (115 200 baud, LF) with the command tree of the manual (section 15): IEEE 488.2 common commands, outputs, frequencies, CH3, all CONFIG settings except `Remote outputs`, diagnosis, log, save, identify. Commands go through the command queue and the controller like touch actions; queries read the state snapshot (V-6).
- **A-63** Numbers are parsed exactly as integers (Hz, 0.01 ppm, %), with the units HZ/KHZ/MHZ, PPM, PCT, DEG, exponents and MIN/MAX/DEF; nothing is clipped: out of range −222, NAN/INF/hex/unknown units/values not in the set −224, wrong data type −104. A command with an extra parameter (−108) or any error changes nothing (W-E18, W-S19).
- **A-64** A line has at most 256 bytes, 16 commands and only printable ASCII or TAB; otherwise it is discarded up to its LF without executing anything (−363, −101, −223) (W-S17).
- **A-65** At most 20 setting commands per second and source; further ones are refused (`-200,"Execution error;Too many commands"`) (W-S11).
- **A-66** The first line over USB starts an SCPI session: log lines go only into the ring buffer (A-61) and the Arduino core's own messages are off until 10 min without a line (W-E27, W-S22). Opening the port with DTR/RTS off does not restart the device.
- **A-67** `Remote outputs` (W-E25, W-S21): `allowed` (default) or `local only`; with `local only` a remote source cannot switch an output on or select off state `High` (`Denied`, SCPI −221, REST 403; E-40), switching off and the off states `Low` and `High-Z` stay allowed. Only the touch source changes it; it is saved at once, kept by `Defaults` and `*RST` and reset by the factory reset.
- **A-68** `SYSTem:IDENtify` blinks the backlight and the RGB LED for 5 s (W-E28).
- **A-71** CONFIG has the rows `WiFi` (Off / Client / Access point, saved and applied at once) and `Remote out.` (allowed / local only, A-67). The MAIN status bar shows the WiFi state (symbol green connected, gray searching; `AP` green, `AP open` in the warning color) and for 10 s after a remote command `REMOTE <source>`, with `LOCKED` taking precedence; no element overlaps another in any combination (widths from the font data, at least 8 px before `CONFIG`). The info card shows the WiFi state and the heap (free, minimum, largest block, LVGL). A foreign string (SSID) reaches LVGL only through `Sanitize::text` (valid UTF-8, no control characters, at most 32 bytes) (W-E26, W-S9, V-8).
- **A-72** WIFI page (`Setup` in the CONFIG row `WiFi`, no scrolling): two network slots with change and delete (with confirmation); a scan lists at most 15 networks, one entry per SSID, strongest first, sanitized, 4 per page, hidden ones via `Other...`; passwords on the on-screen keyboard (8–63 printable characters or 64 hex digits as PMK, D31; the AP password 8–63; show/hide, counter), an open network only after a warning; a stored key is never shown. A status line gives the WiFi state and the reason of the last failure (wrong password, not found). With two stored networks the strongest seen is tried, but after a failure the other one if it is seen too (W-E2, W-E7, W-S9).
- **A-73** Access point page: QR code `WIFI:T:WPA;S:…;P:…;;` (open: `T:nopass`, special characters escaped) on a white quiet zone, name, password in clear, address; the random password exists from the first visit on (bootloader entropy source while the radio is off); `Regenerate`, own password 8–63 characters, open only after a warning and switchable back; a running AP restarts with new data without touching the client connection. An open fallback AP starts only after the touch confirmed it (W-E3, W-S1, W-S2).
- **A-74** Device page: device name (RFC 1123 label, 1–32 characters `a-z0-9-`, announced as `<name>.local`) and IP mode DHCP/static with address, mask, gateway, DNS (empty = gateway); switching to static prefills empty fields from the DHCP lease; an implausible combination (mask not /1–/30, address or gateway missing, address = gateway, gateway outside the subnet, network or broadcast address) is refused with the reason and the stored value stays. Changes at the touch apply at once; the two-stage change with fallback (W-S12) applies to remote changes (W-E4, W-S12). The web password (8–64 characters) is set, changed or removed there (removing after a confirmation); it is never shown, hashed outside `loop()` with a salt from the true random source, and every change ends all web sessions without restarting the WiFi. The info card shows the remote clients and can disconnect all of them.
- **A-75** SCPI over TCP on port 5025 while the client is connected or the AP runs with a password (never over an open AP), announced as `_scpi-raw._tcp`: one connection (a second one is closed without an answer), own error queue and status registers cleared per connection, the same line limits as USB; a line that looks like an HTTP request closes the connection before anything of it runs (W-S18); idle 10 min and keepalive 60/10/3 s close it; answers are sent per line without blocking `loop()`, a peer that does not read is closed when the buffer is full. Commands are never logged (W-E12, W-E13, W-S20). No authentication: the web password does not apply, every command (also `*RST`, `SYSTem:SAVE`) is open to anyone who reaches the port; protection is `Remote outputs: local only` and a trusted network (E-41).
- **A-76** Web server on port 80 while the client is connected or the AP runs: the embedded web UI and the REST API/WebSocket of ARBEITSPLAN 3.6. Every request passes the request guard (host allowlist without IPv6, origin, `Sec-Fetch-Site`, token, content type, session) and the W-S10 limits on the raw bytes before parsing (URL 256 B, headers 2 KB, body 1 KB, 10 s per request, at most 4 HTTP connections and 3 WebSockets, 24 KB free heap and an 8 KB free block for a new connection); WebSocket pushes at most every 100 ms and only with a free block for them; security headers and CSP without inline code. Writes answer with a state that contains them. The web password check (PBKDF2) never runs in the network task; 5 failures lock the login for 30 s, doubling up to 960 s. A network change from the web stays only when confirmed within 120 s over the new connection and, without a web password, also at the touch screen; `Off` is final. With a web password reading needs the login as well (state, token, WebSocket; only the page and the LXI identification stay open, D25, D33, E-48). While it is open only the confirmed state is saved (after a power loss the previous settings apply), the touch screen changes no network settings and offers `Revert` (E-47). Password fields are refused over an open AP, in every POST body including the login (W-S1, W-S4–W-S13, W-S23).
- **A-78** LXI discovery and VXI-11 (LX1) under the same gate as SCPI over TCP (A-75; one condition switches both): a portmapper (program 100000 version 2) on UDP and TCP 111 answers NULL and GETPORT, also to broadcasts (`lxi discover`), and DUMP over TCP only; GETPORT knows only the VXI-11 core program (0x0607AF v1 TCP) and the portmapper itself, other procedures give PROC_UNAVAIL, rpcbind versions 3/4 PROG_MISMATCH 2..2; over UDP no reply is larger than its request and at most 20 replies per second are sent; over TCP two connections at a time, a further one replaces the one idle the longest. The VXI-11 core channel on TCP 9009: one connection with one link (`inst0`), create_link, device_write, device_read, device_readstb, device_clear, device_lock/unlock, device_remote/local and destroy_link on an own SCPI session (source SCPI, line limits of W-S17, `Remote outputs` applies, error queue cleared per link), END flag and termination character, maxRecvSize 1024, records up to 2 KB (a larger one closes the connection), idle 10 min and keepalive as A-75; device_trigger, device_docmd, SRQ and the interrupt channel answer error 8, no abort channel (abortPort 0). mDNS announces `_lxi._tcp` (port 80, TXT with manufacturer and model only, W-S16), `_vxi-11._tcp` (port 111) and `_http._tcp` besides `_scpi-raw._tcp`; `GET /lxi/identification` returns the LXI identification XML through the request guard (Host check as for the pages), with the `*IDN?` serial number and without MAC or commit, readable without login also with a web password (D33). No authentication and no setting of its own (as A-75, D24); calls are never logged (E-37).
- **A-69** Network settings live in their own NVS namespace `hfnet`: mode (default Off), at most two networks, AP password, open AP flag, device name, static IP. A WiFi key is stored as entered: passphrase (8–63 characters) or 64-digit hex PMK (E-30), accepted the same way at the touch keyboard, over REST and in the web UI (`NetConfig::validNetworkKey`, D31); it is never shown, logged or exported; the AP password is 12 random characters without 0/O/1/l/I; the device name follows RFC 1123 (default `cyd-hf-<last 4 hex digits of the MAC>`); a static IP must pass the plausibility check (contiguous mask /1–/30, address and gateway different and in one subnet, neither network nor broadcast address), else DHCP applies. Invalid stored values fall back to the defaults. The factory reset erases `hfnet` and the WiFi driver's namespace `nvs.net80211` (W-E3, W-E5, W-E7, W-S12, W-S14, W-S16).
- **A-70** WiFi operation (W-E1, W-S2, W-S3): `Off` keeps the radio off. `Client` scans asynchronously and connects to the strongest stored network (a network not seen, e.g. hidden, is tried in turn), at least WPA2 unless the network was stored as open, 15 s per attempt; without an address for 60 s it starts the fallback AP and keeps searching. The AP (`Access point` mode or fallback) is `CYD-HF-<last 4 hex digits of the MAC>` at 192.168.4.1/24 with WPA2 and the random password (created on first use while the radio runs), at most 4 stations (open: 2, and only after a touch confirmation as fallback; off after 15 min without station); its DHCP server offers no router but itself as DNS server, a captive DNS answers every name with 192.168.4.1. As soon as the client has an address the AP goes off within 1 s (D14). mDNS announces `<name>.local`. The WiFi driver stores nothing itself (`WiFi.persistent(false)`). Nothing of it runs in the WiFi task; `loop()` is never blocked (no `WiFiMulti::run()`).

## 4. Decisions

### E-1 Fixed touch calibration
*Original specification; superseded by E-27.* Runtime calibration and its UI are disabled; all devices use `TOUCH_CAL_DEFAULT` (x 300–3800, y 300–3800). Touch works with these values on both boards (hardware tests I1, I2); hits at the screen edges are checked by B7.

### E-2 Global drive strength
*Original specification.* One CONFIG value `Drive all` for CH1–CH3; CH3 has no own setting, so master and follower of an IQ pair always drive alike. The per-channel fields were removed (stored key `drv_def` unchanged). Drive per channel is an open question (ARBEITSPLAN 1.3, question 1c).

### E-3 RGB LED shows the open channel page
*Original specification, confirmed.* The LED is not used as an output indicator.

### E-4 XPT2046 library from GitHub
*Original specification.* Installed by URL `#v1.4`, because the PlatformIO registry version was unreliable.

### E-5 Numpad with back key and validation
*Approved.* Original: no cancel button, 5-row grid. Now a 4 × 4 grid, back key `◀` to the channel page, current frequency as placeholder, invalid input rejected instead of clamped. Reason: keys were about 14 px high, and `MAIN` discarded the input and jumped one level too far.

### E-6 Correction in ppm
*Approved.* Original: buttons ±10 / ±1 without unit. Now shown in ppm, steps 0.01 / 0.1 / 1 ppm, hold-to-repeat, ±50 ppm. Reason: the unit is 0.01 ppm, so typical crystal errors needed hundreds of taps.

### E-7 IQ range 4.730–100 MHz, 180°/270° via CLK_INV
*Approved.* Original: 1–100 MHz with the phase register only. Reason: the former library clamped IQ at 1.4 MHz and ran the VCO below 600 MHz under 4.725 MHz (600 MHz / 127); with the phase register alone, 180°/270° were possible only from 14.3 / 21.4 MHz.

### E-8 CH3 ON as a request
*Approved.* Original: CH3 was disabled on an invalid phase. Now the request is kept (WAIT) and CH3 starts automatically. Reason: the user's choice was lost and CH3 never came back after a frequency change.

### E-9 Requested frequency stored exactly
*Decided.* The device keeps and shows what the user entered; the SI5351 rounding is shown separately as actual frequency (A-14).

### E-10 Own SI5351 register driver
*Approved.* Replaces osmanovv/esp32-si5351 plus direct writes into its internals. Reason: the library applied the correction to a frequency truncated to whole MHz, reset the PLL on every change and limited IQ (E-7). The own driver follows AN619 with exact correction, register cache, PLL reset only on change and supervision. Measured in host tests against the register model: ≤ 0.375 Hz for 1–100 MHz at correction 0. Formulas and register details are documented in `si5351_manager.*` and `si5351_plan.*`.

### E-11 All outputs start off
*Approved.* Before, stored ON/OFF states were restored. Reason: a connected mixer, amplifier or circuit under test must not get a signal before the user switches it on.

### E-12 Output error state ERR with silent retry
*Decided.* A setup that fails while the SI5351 answers is not a lost device: it is shown as ERR, the switch keeps the request, one dialog appears and the setup is retried every 2 s without further dialogs. Test hook `TEST_FAULT_IQ=1` (`config.h`) makes the IQ setup fail at 270°.

### E-13 ON/OFF text next to the header switch
*Changed (audit U-1).* The text state stays next to the switch; it is readable without interpreting the switch graphic. It shows the actual state like MAIN (also WAIT and NO HW) instead of the request, which the switch already shows: before, the header said ON while CH3 was waiting or the SI5351 was missing.

### E-14 Verbose logging only with LOG_DEBUG
*Decided.* Blocking serial output slows down the GUI. `CORE_DEBUG_LEVEL=1`, because the I2C detection re-initializes the bus, which the core logs at info level.

### E-15 Host unit tests
*Decided.* Driver math and controller logic are tested without hardware. `test/fakes` replaces Arduino, `Wire` (SI5351 register model with fault injection) and `Preferences`; `test/helpers/si5351_model.h` decodes the written registers independently of the driver's arithmetic, so a wrong formula cannot confirm itself. A check with deliberately inserted faults (correction sign, phase offset −1) made the affected tests fail.

### E-16 Frequency range 8 kHz–160 MHz
*Decided and implemented.* CH1/CH2 cover 8 kHz–160 MHz; CH3 stays at 4.730–100 MHz (IQ divider 9…127) and waits above. Below 1 MHz the R divider (2^1…2^7) keeps the MultiSynth input at ≥ 1 MHz; the display switches to kHz. Above 100 MHz `Fractional` tries the largest even integer MultiSynth (8/6/4) with a fractional PLL when the fixed PLLs miss by more than 0.25 Hz; next to 112.5 MHz the MultiSynth ratio rounded to exactly 8 and missed by up to 5 Hz before (fixed in S34). From 112.5 MHz on every step changes the PLL and resets it (short dropout). Level and harmonics are not measured yet (MESSPLAN H1, H2); the channel page shows a hint outside 1–100 MHz. On MAIN the `~` of `Integer` is left out from 100 MHz on (does not fit the card; the mode line shows `Integer`).

### E-17 Automatic SDA/SCL detection and identity check
*Requested.* Reason: the original specification and the verified device disagreed on SDA/SCL, and cables get swapped in the lab.
- `AppController::connect_()` tries the open assignment first, then the other. Per assignment: address probe (0 ACK, 2 NACK, 5 timeout), then `SI5351Manager::begin()` with identity check. A failed init still tries the other assignment, because weak pull-ups can fake an ACK.
- Identity, read-only: register 0 = 0xFF, register 183 = 0x00 / 0xFF or XTAL_CL = 00 reject the device (`NotSi5351`). Register 183 bits 5:0 ≠ 010010b or a SYS_INIT that stays set only log a warning (clones). Then register 3 is written with 0xFF and read back; a mismatch rejects the device (`NoReadback`). Init writes stop at the first error.
- A rejected device is marked for its assignment. After `NotSi5351` the read-only check repeats every cycle (an SI5351 still powering up passes later); after `NoReadback` the device is left alone until it stops answering. A successful connection clears the mark.
- `LinkState`: NotFound (silent retry), Blocked (line held low), UnknownDevice, Connected. A dialog appears once per change to Blocked / UnknownDevice; at boot for every state except Connected.
- 100 kHz for detection, 400 kHz after init; the connection stays at 100 kHz if the read-only check fails at 400 kHz (weak pull-ups). `Wire` timeout 20 ms.
- Line release at boot: 9 clocks and a STOP on each pin (open drain with internal pull-up, 10 µs half period).
- Arduino-ESP32 2.0.x leaks the `Wire` lock on a transfer while the bus is not started, and the next transfer deadlocks (A-40). `I2CBus::open()` treats a failed `Wire.end()` as a closed bus.

### E-18 One firmware with display controller detection
*Requested.* Replaces the separate environment `esp32-2432S028R-usbc`, because the boards look alike and the wrong firmware shows only noise. Measured on both boards (diagnostic sketch):

| | Original CYD | CYD2USB |
|---|---|---|
| MADCTL read-back (0Bh after writing A8h / 54h) | exact, no dummy bit | exact, no dummy bit |
| RDDID (04h, one dummy bit) | `00 00 00` | `81 81 B3` |
| RDID4 (D3h) without the 0xD9 index trick | not driven | not driven |
| MISO with internal pull-up / pull-down | data stays valid | the pull overrides the panel completely |
| Error-free read clock | up to 16 MHz | up to 8 MHz |
| Writes at 40 MHz, SPI mode 0 and 3 | error-free | error-free |

After the ILI9341 init sequence the ST7789 reports ID1 = 0x10 (C1h is IDSET there); SWRESET restores it.

- Probe before `tft.init()` at 1 MHz, mode 0, GPIO12 without pull: SWRESET; MADCTL A8h / 54h written and read back (the XOR must show FCh in bits 7:2, which rejects a floating or stuck MISO); RDDID read twice and compared. ID `000000` → ILI9341, `FFFFFF` → unknown, any other → ST7789 (unknown IDs logged). At most 3 attempts of about 20 ms.
- Order: build flag `DISPLAY_FORCE_PANEL` (1 / 2) → detection → ILI9341. A boot gesture that could select the other controller and store it in `disp_panel` was removed (E-26).
- Init: TFT_eSPI (built for the ILI9341) sends its sequence on both boards; on the ST7789 `DisplayDetect::postInit()` sends SWRESET, 150 ms and `ST7789_INIT`, copied from TFT_eSPI 2.5.43 (hence the exact version pin), and `DisplayPanel` writes the ST7789 MADCTL (`08 68 C8 A8` for rotation 0..3 instead of `48 28 88 E8`).

### E-19 Tuning modes, default Fractional
*Decided.* Reason: in `Fractional` the MultiSynth almost always divides fractionally (host analysis with random frequencies of 1–100 MHz: 0 % in integer mode; with correction ≠ 0 not even 10, 25 or 50 MHz), which causes spurs near the carrier.
- `Low noise` follows the method of the QRP Labs and Etherkit VFOs: the largest even divider with VCO ≤ 900 MHz, kept with hysteresis while the VCO stays within 600–900 MHz (e.g. divider 90 covers 6.67–10 MHz). Whether the PLL takes small changes without reset is checked by measurements D5 / K6; if not, the PLL is reset on every change.
- `Integer` gives the lowest spurs and shows the fractional/integer difference most clearly in training. The raster is computed from the corrected crystal, so the correction cannot be compensated and only shifts the displayed actual frequency (7.1 MHz → 25 MHz × 25 / 88 = 7.102 273 MHz). `FBA_INT` / `FBB_INT` are set when the PLL ratio is integer and no spread spectrum runs on PLL A.
- Default stays `Fractional` (tuning without dropouts). Measurements K5 / K6 decide whether `Low noise` becomes the default.

### E-20 Spread spectrum on PLL A only, default Off
*Decided.* AN619 provides spread spectrum only on PLL A; the option is therefore called "Spread CH1". AN619 allows down spread −0.1 … −2.5 % and center spread ±0.1 … ±1.5 %; the selection is kept small (Off, −0.5 %, −1.5 %, ±0.5 %). Parameters (registers 149–161) are recomputed on every PLL A change. Spread spectrum needs a fractional PLL A, hence locked in `Integer`. The setting is written explicitly at init (`SSC_EN` = 0 for Off), because modules with programmed NVM could start with spread spectrum on. Default Off: spread spectrum widens the spectrum, which is unwanted in mixer experiments. The modulated VCO must stay within 600–900 MHz, so with spread the unmodulated VCO is limited to ≥ 600 MHz / (1 − amp) and, for center spread, ≤ 900 MHz / (1 + amp): `Fractional` uses the fixed PLLs 887.5 / 875 MHz for center spread, `Low noise` and IQ choose their divider in the narrower window. The IQ range with master CH1 therefore shrinks (−0.5 %: from 4.748 151 MHz; −1.5 %: from 4.796 355 MHz; ±0.5 %: 4.748 151–99.502 487 MHz); outside it CH3 waits instead of failing (`iqMinHz()` / `iqMaxHz()` in `si5351_plan.*`).

### E-21 Off state option, default Low
*Decided.* Originally register 24 was never written; switched-off outputs were LOW (reset value 00), while the documentation wrongly claimed High-Z. `Low` stays the default: unchanged behavior and suitable for DC-coupled mixers (diode ring, FST3253). `High` drives DC into a DC-coupled load (current limited by the drive strength). Code 11 (never disable) is not offered.

Whether `CLKx_PDN` leaves a pin high-impedance or pulls it low is unmeasured (hardware test K2). Until then, outputs keep their driver powered with `High` and `High-Z` (output enable off only, also for CLK2); with `Low`, CLK2 is powered down as before. If K2 shows high impedance, `High-Z` will power down all switched-off outputs.

### E-22 CONFIG scrolls, all other pages stay fixed (replaced by E-42)
*Decided.* Supersedes the earlier "no scrollbars" rule, whose cause was unwanted scrollbars from overlapping elements. CONFIG needs seven rows of 48 px plus the info card (≈ 414 px) in 202 px below the header. Only the content area scrolls: snap to rows, no elastic overscroll, scrollbar always visible (4 px), the fifth row visibly cut at the bottom edge; the header with the save state stays fixed. The scroll position is kept in RAM when returning from MAIN. Scrolling starts after 10 px (`LV_INDEV_DEF_SCROLL_LIMIT`); a swipe that starts on a button gives `PRESS_LOST` and neither a click nor a repeat (hardware test K10).
*Revised:* six rows of 50 px (the `Step` row duplicated the chips of the channel pages, audit U-14), order Drive, Off state, Tuning, Spread, Corr., Backlight (signal settings first), buttons 40 px (U-18). Three rows and 36 px of the fourth are visible, the scrollbar is 6 px wide with 5.7:1 (U-24); a "more" label at the bottom edge was tried and dropped in the operating test (it covered the cut row, the wider scrollbar was enough). Dropdown lists use 9 px line spacing, so a 4-entry list (103 px) opens completely in every snap position.

### E-23 Backlight 10–100 % in 10 % steps
*Decided.* Replaces the slider and its 5 % minimum. Reason: a swipe on a slider in the scrolling page would change the brightness; `−`/`+` without repeat need at most 9 taps. Older stored values are rounded to the nearest step; values below 5 % give 80 %. Readability at 10 % is checked by hardware test K12. PWM 5 kHz, 8 bit.

### E-24 Build information
*Decided.* `tools/build_info.py` (PlatformIO `extra_scripts = pre:`) determines branch, commit, dirty mark and local build time and passes them only to `src/utils/build_info.cpp` (`env.AddBuildMiddleware`), so each build recompiles just this file. `__DATE__` / `__TIME__` are unsuitable: the file would not be recompiled and the date would go stale. Shown on the CONFIG info card and in the boot log line; not part of the host tests.

### E-25 Documentation roles
*Decided.* Specification = requirements and decisions; behavior only in `USER_MANUAL_DE.md`; `USER_MANUAL_EN.md` is its translation with the same structure and tables, updated in the same commit. Reason: the former specification (1401 lines) and both manuals described the same behavior and had drifted apart.

### E-26 Boot gesture removed, detection only
*Decided.* The boot gesture (touch held 1.5 s from power-on: use the other controller and store it) could fire by accident with a thumb on the screen while plugging in, and stored a wrong controller that only a second gesture without a readable screen undid (audit U-10). The detection (MADCTL read-back, RDDID read twice, up to 3 attempts) worked reliably on both boards in all tests. Decision: no runtime override; the build flag `DISPLAY_FORCE_PANEL` stays as the fallback for an unknown board. The NVS key `disp_panel` would otherwise override the detection forever and is deleted at boot. A touch at power-on is still kept away from LVGL.

### E-27 Touch calibration per board
*Decided.* The hit map (MESSPLAN B8, test build of S28) showed the fixed calibration (x 300–3800) off on both boards: hits 11–19 px too far left on the original CYD, x = 80 by about −17 px and the right edge by −1 … −7 px on the CYD2USB; the right corner was not reachable on the original CYD (audit U-26). Requested by the user: a calibration at the very first start. Four crosses 20 px from the corners give offset and slope per axis (linear, as `mapPoint()`), the cross in the middle checks it (≤ 8 px; the hit map scattered by about ±5 px with a good calibration); each cross is held 0.5 s, the first 0.1 s are not averaged. First results: x 161…3778 / y 245…3830 (CYD2USB) and x 166…3716 / y 280…3885 (original CYD), check −2/+2 and −2/+1 px. Stored in NVS outside the autosave; without a stored calibration the wizard runs at boot, 30 s without a touch continue with the default, so a board with a defective touch stays usable. A CONFIG row starts it again.

### E-28 LVGL 8.4.0, not LVGL 9
*(migration, ARBEITSPLAN S40a).* 8.4.0 is the last LVGL 8 release. Against 8.3.11 it changes almost only formatting; in content the screen load order, a group focus swap and a cast in `lv_obj_style.h` that removes the C++20 enum warning of GCC 14 (Arduino 3.x); the widgets the GUI uses (label, button matrix, dropdown, switch, textarea, message box, scrolling, input) are unchanged apart from whitespace, `lv_conf_internal.h` and the template keys are identical. Measured on the original CYD (debug build): first frame 159 ms (2.x core, as 8.3.11) and 169 ms (3.x core, 172 ms with 8.3.11), heap and LVGL memory unchanged, flash +72 B. LVGL 9 is not used: new display, input, style and widget APIs would mean rebuilding every page and a full operating test, for no feature the device needs.

### E-29 SCPI on scpi-parser with own number parsing
*(ARBEITSPLAN S51).* The command tree runs on j123b567/scpi-parser (BSD-2): header matching with short/long forms and suffixes, error queue and IEEE 488.2 registers are tested there and fuzzed (issue #174: about 95 M executions of lexer and parser clean; the three findings are in the example code, which is not used). Pinned to commit `886615902b2777b71860445305bfe5a3faef4f3e` = v2.3 plus `strings.h` for `strncasecmp` and a `-Wdouble-promotion` fix. Configured identically for the ESP32 and the host (`include/scpi_user_config.h`): full error list, error info in a fixed 256-byte buffer per session (no malloc), LF line ending. Numbers are not converted through the library's `double`: `remote/scpi.cpp` parses the token text into exact integers, so `7.1E6` and `10.0000005 MHZ` give 7 100 000 and 10 000 001 Hz without binary rounding. Two deviations from the concept: the library knows no optional first node, so `[SOURce<n>:]` is listed twice; the actual output state is `OUTPut<n>:CONDition?` instead of `:STATus?`, because the short form `STAT` would also match `STATe`. `SYSTem:LOG?` returns one line per query, so line-based clients need no block format. Measured on the CYD2USB (Arduino 3.3.12): 1000 × `*IDN?` without error, median 6.0 ms, 99 % below 11.6 ms; flash +24 KB, RAM +1.3 KB.

### E-30 WiFi key stored as passphrase, not as PMK
*(ARBEITSPLAN S52b, D15, decided by the user).* The concept (W-S14) stored WPA2 keys only as PMK, so a flash dump would not reveal a passphrase used elsewhere. On the office network (WPA2/WPA3 transition mode) a PMK never connected (reason 2 and 202, AUTH_EXPIRE/AUTH_FAIL): ESP-IDF 5.5 always chooses WPA3-SAE when the AP offers it, and SAE needs the passphrase; `pmf_cfg.capable` is deprecated and SAE is compiled into the precompiled IDF, so neither can be switched off. With the passphrase the same network connected in 3.4 s. WPA3 and transition networks are the normal case on current routers, so the key is stored as entered (passphrase, or a PMK typed as 64 hex digits for pure WPA2 networks). *(AF8, D31, audit DOC-13):* the touch keyboard refused the PMK while REST took it; now one rule (`NetConfig::validNetworkKey`) applies at the touch keyboard (64 characters for a network key), in REST and in the web UI. It is readable with a flash dump, as everything else without flash encryption (S-22); it is never shown, logged or exported, the interfaces only say set/not set. The PBKDF2 code stays for the web password hash (W-S13). Measured on the CYD2USB with a phone hotspot: fallback AP after 61.9 s without connection, AP off 0.1 s after the client got its address (D14, log resolution 0.1 s); flash +660 KB for the WiFi stack (1 352 091 B, 43.0 %), RAM 124 220 B.

### E-31 LVGL memory pool from the heap
*(ARBEITSPLAN S53b).* With the WiFi stack the static data reached 124 KB and the next 1 KB (scan list) overflowed the DRAM segment `dram0_0_seg` by 728 bytes. The 48 KB LVGL pool is therefore allocated with `malloc` in `lv_init()` (`LV_MEM_POOL_ALLOC`) instead of being a static array: static RAM 76 KB, after boot with WiFi in Client mode 136 KB heap free, minimum 129 KB, largest block 61 KB (warning limit 40 KB). The pool size is unchanged; the allocation happens once at boot, before any network buffer.

### E-32 Arduino-ESP32 core 3 only

### E-37 VXI-11 with an own portmapper; core channel on fixed port 9009
*(ARBEITSPLAN LX1, D24, D33).* LXI tools find instruments by a portmapper GETPORT broadcast to UDP 111 (lxi-tools `lxi discover`, pyvisa-py `list_resources()`) and reach `TCPIP::<ip>::INSTR` through the portmapper on TCP or UDP 111; mDNS (`lxi discover -m`) lists the device but gives no VISA client the core port. The device therefore runs a minimal portmapper of its own (version 2, three fixed mappings) instead of rpcbind: no SET/UNSET (nothing registers at run time) and no CALLIT, which would forward calls and make the device a UDP reflector; over UDP a reply is never longer than its request and at most 20 replies per second leave. rpcbind versions 3 and 4 get PROG_MISMATCH 2..2; libtirpc (lxi-tools on Linux and Windows) then keeps that TCP connection to port 111 open and asks GETPORT version 2 on a second one, so the portmapper takes two TCP connections, and a third replaces the one idle the longest (it is stateless; an idle client cannot lock it). A one-connection portmapper made `lxi scpi` fail with "Unable to connect" (found in the interop test, host test `test_portmap_tcp_pool`). The core channel listens on the fixed port 9009 instead of an ephemeral one: one listener for the whole uptime, stable firewall rules, a documented port. HiSLIP was not chosen: lxi-tools, pyvisa-py and python-vxi11 all speak VXI-11, HiSLIP needs two channels per session. Limits as for SCPI over TCP: one connection with one link, records up to 2 KB (maxRecvSize 1024; the largest device_write with AUTH_SYS credentials fits), answers up to 2 KB per line, reads up to 1 KB; no abort or interrupt channel, `device_trigger` unsupported (no trigger system). A read with no answer waiting gives error 15 at once: commands run synchronously in `loop()`, so waiting for io_timeout could only block. A new message while an answer is unread discards it with -410 (IEEE 488.2); `device_clear` keeps the error queue (DCL). Parsing and encoding are pure and host-tested (`onc_rpc`, `vxi11`, test_vxi11) and fuzzed (`vxi11`, 1 000 000 standalone inputs clean); the lwIP glue reads at most up to the end of a record, so at most one reply waits. The host test found a 32-bit wrap in the XDR opaque length check (`0xFFFFFFFF + 3`), fixed before it shipped. No authentication and no setting of its own, like SCPI over TCP (audit SEC-1/DOC-1, D24: usual for lab instruments, protection by a trusted network and `Remote outputs: local only`); both use one gate (`ScpiTcpLink::allowedFor` in `pollNetworkScpi()`), never over an open AP. `/lxi/identification` stays readable without login also when a web password is set (D33): it holds only what `*IDN?` gives over network SCPI anyway, and LXI tools read it without credentials; the request guard asks a session for reads only under `/api/` and `/ws`, `test_http_guard` pins the exception. Checked on the host with the firmware logic behind a socket shim on 127.0.0.1: lxi-tools 2.8 for Windows (`lxi scpi`, `-x`, `lxi benchmark -c 500`), python-vxi11 0.9, PyVISA 1.16.2 with pyvisa-py 0.8.1 (query, read_stb, clear, lock, timeout, the pyvisa-py broadcast client) and `tools/lxi_example.py`; `lxi discover` found the fake device (`tools/fake_scpi_device.py --vxi11`); `lxi discover -m` and the device itself are still open. Flash +10.5 KB (1 518 166 B against 1 507 646 B), static RAM unchanged (78 432 B), heap about 8.5 KB for the server object from boot plus 1.3 KB per identification request while it is sent.

### E-46 WiFi search with backoff
*(ARBEITSPLAN AF14, D32, audit PERF-5).* The client scanned actively every 15 s while it had no address, also without any stored network and next to the fallback AP, which leaves its channel for every scan (about a quarter of the time with the 15 s attempt that followed), and `WiFi.begin()` for an unseen stored network (hidden SSID) followed every scan. ### E-47 One owner of the network settings during a web change
*(ARBEITSPLAN AF16, concept 2, audit CQ-2).* A web network change kept the previous settings for up to 120 s while the WIFI pages stayed usable: a revert threw away every touch change of that time (also a new web password), and a touch change saved the unconfirmed web state, which then applied after a power loss (against W-S12). ### E-48 With a web password reading needs the login; WebSocket control frames bounded

### E-50 REST writes and WiFi jobs wait for loop() without polling and are answered later when it is slow; JSON without allocations
*(ARBEITSPLAN AF54, audit PERF-7, PERF-9, W-S23).* A REST write or a WiFi job (change, confirmation, scan) blocked the `async_tcp` task for up to 80 or 180 ms, checking the result every 1 ms, and every state JSON built an ArduinoJson document with about 20–30 heap allocations.
